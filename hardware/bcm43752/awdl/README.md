# BCM43752 原生 AWDL 后端

本目录是已完成固件、DHD、BCM 主机后端、公共 Rust 组件构建及用户态暂存安装，尚未完成真机验收的实现候选，不代表 BCM43752 已支持可交付的双向 AirDrop。

`bcm43752-awdl` 由公共 `wirelessd` AWDL 管理器启动，复用 `components/awdl` 的发现、对端选择和日程计算，复用 `hardware/bcm43752/hostap` 的 Netlink、PHY 和 NDI 所有权代码。AirDrop HTTP/TLS、发送、接收和 D-Bus 服务保持公共实现。

后端依附已运行的原生 NAN，创建独立 NDI `awdl0`。主设备保留 DHD 命令节点，不启用 STA/AP/P2P/monitor。固件用独立会话代次管理 AWDL BSS、SCB、MSCH 和管理帧完成回调；普通 NAN 的密钥与授权检查不改作 AWDL 的授权路径。DHD 在该 NDI 上恢复 Apple MSDU 封装，以内核 IPv6 收发数据，并对该会话采用软件发送校验和及分段、软件接收校验和及 GRO。

调用契约与 BE200 后端一致：

```
bcm43752-awdl phyN 149 TARGET LOCAL_NAME
bcm43752-awdl phyN stop
```

主信道也可为 `161`，跟随范围为同一 80 MHz 频块内的 149/161。真实 PHY 能力来自 wiphy，信道由固件 CLM 最终检查。标准输入接受 `SELECT TARGET` 和 `STOP`，标准输出发送公共管理器消费的 JSON 事件。`started` 表示初始化命令已完成，不表示发现对端或文件传输已通过。

传输配置来自 `hardware/bcm43752/radio.toml`，通过公共管理器传入 `AWARE_AWDL_TCP_CONGESTION`、`AWARE_AWDL_INITIAL_WINDOW`、`AWARE_AWDL_REORDERING`、`AWARE_AWDL_TX_QUEUE` 和 `AWARE_AWDL_TX_DRAIN_TU`。字段含义、单位、范围及必填约束见该配置；后端不静默采用另一套默认值。会话安装永久 IPv6 邻居、1100 ms 最小 RTO 的对端路由、fq 队列，并删除该地址对的旧 TCP 指标。默认仅保留 2.4 GHz NAN 发现；带固件时间戳的原生发现窗口通知用于扣除 AWDL 接收日程中的离开时段。

日程和公共控制器使用 MSCH 微秒时钟。接收公告从原生 RX 元数据恢复 MAC 时间，以当前 MAC 时间计算帧龄，再用两次 MSCH 采样的中点减去帧龄得到调度时钟中的接收时间；原始 MAC 时间不能直接充当 MSCH 期限。换算仍包含采样间隔内的不确定性，不能宣称精确到空口接收瞬间。主机通过 QUERY 的往返采样估计唤醒时间，每秒刷新映射；刷新不转换或移动已安装的时隙。换算后的接收时间送入公共控制器，管理帧由固件在原生 DMA 提交前按会话的固定时钟原点填写物理时间戳，包含主机传递、信道等待及固件队列等待；DMA 重新提交时再次更新。匹配仅限会话实际持有、正在提交或已入队的管理帧。时间戳不包含 DMA 提交后的硬件等待。会话代次变化或固件时钟倒退均报告错误并进入实际资源清理。

停止先关闭数据准入，等待 DHD 真实队列清理，再释放固件管理帧、调度和对端，最后删除 NDI。失败保留实际代次和接口所有权，可通过再次 `STOP` 重试；进程重启后的 `stop` 从固件及 DHD 查询恢复清理责任，不靠删除状态文件宣称成功。每个 PHY 的进程锁保留在 `/run/lock`，防止运行中另一个清理进程接管。

固件代码与完整 Flashpatch 表保留在 `[0x172000, 0x180000)`，共 56 KiB。原生低地址附加堆截止点与执行区起点同步调整；附加堆保留 7,163 字节。固定原生函数使用带 Thumb 类型的链接符号，汇编入口禁止跨过程改写；GCC 16.2.0 以 C23、Oz 和 LTO 构建。当前发送者通知候选代码 54,148 字节，加补丁表共 57,280 字节，余量 64 字节。原生堆登记、三次 reclaim 和 MPU 划分的离线执行确认补丁不进入堆、全区只读可执行；这不证明真实分配余量和启动稳定性。原始固件及授权仍按硬件目录的固定来源管理。

静态分析确认普通／快速接收和 A-MSDU 解聚合均保留 Apple LLC，DHD 解封装位于原生 PCIe 接收链的协议分类之前。NAN 数据槽广播跳过 AWDL NDI；AWDL 仅由自己的 MSCH 回调开关信道。优先级为发现 DW 4、AWDL 3、普通 NAN 数据 2。活动 NDP 与 AWDL 并发的吞吐与公平性尚未验收。

候选固件 SHA-256 为 `71a802cf631e47011652353fa52948172cff4c0b8de552bc9130fd92ec1d0b5f`，固定输入、原始补丁字节、容量、逆向还原及原生堆／MPU 离线执行检查通过；已加载到 RK3568。该镜像的 iPad Pro 1 GiB 正向文件验收失败：接收端已接受，发送端最终报告“AirDrop 未交付文件”（退出码 1），未取得完整交付及内容校验证据。结束时服务记录 `stopped cleanup=0 rc=0` 和 `released`。双向 AirDrop 文件验收尚未通过。

十六槽 MSCH 日程使用连续信道列表与可抢占标志。AWDL 自有 BSS 的站点初始化保留空的 NAN cubby，不要求 NDP 对端；普通 NAN 仍使用原生初始化及密钥流程。真实信道打开事件先调用原生 BCMC 频段更新函数，再提交 `on_channel` 并通知原生 BSS 队列；原生 HRT 在保护间隔结束及排空期限到达时更新队列可用性，信道关闭和 STOP 取消定时器。普通 NAN 不使用该定时器。

发送封装按自有 BSS、地址与授权确认归属，不依赖尚未写入的 SCB 标签。原生批量路径只复制 8 字节 LLC，且替换头包时不迁移 PKTLINK；AWDL 因此先拆开主机批量链，再逐包准备 16 字节 Apple MSDU 头，保留底层 SCB/D11 聚合与完成回收。额外头部预留只作用于 AWDL。

A2 原生 DMA 分派只检查头包标志。AWDL 的替换头包可以是本地分配，后接含主机 PCIe 地址的 TXFRAG；本地 DMA 分支会跳过该主机载荷。发送边界现在为这种自有链选择原生分片 DMA，保留共享 DMA 寄存器选择、原有包标志、所有权和完成回收；已有分片头及 header-split 链沿用原生分派。DHD 每个 MSDU 提交一个主机 DMA 范围，PKTLINK 批量与 PKTNEXT 分片分别处理。

管理公告按原生 NAN 时隙入口的顺序，在 AWDL 信道打开时调用 `0x301a4 → 0x1284bc` 更新自有 BSS 的 BCMC 频段，保留原生队列的频段检查。修复前采样的 69 次完成回调均来自频段不一致的释放分支，说明 PCB 状态 0 不能作为已发射的证据；修复后 iPad Pro 已建立对端缓存并完成 mDNS 与 AirDrop Discover。

主机区分固件明确拒绝与传输状态不确定：资源不足或队列忙的明确拒绝释放未取得的 cookie，保留最新公告等待后续协议 tick／信道事件；不确定失败保留 cookie 进入 STOP，其他错误不被后续时钟转换覆盖。该处理避免固件没有入队却永久等待 TX_DONE。

普通时隙不可用时使用原生 CLOSE 通知，保留待发数据。原生 OPEN 在对端不可用时会过滤并释放该站点队列，还会清空聚合缓存，不能用来表示临时离开；该释放路径只在真正移除对端时显式调用，并等待实际引用归还。START 限制排空间隔小于一个 64 TU 时隙，因此排空判定只需检查紧邻的下一槽及溢出边界，同信道的下一槽可连续发送。

iPad Pro 已接受 1 GiB 文件请求，但尚未完整交付。队列关闭修复前的完整验收中，TCP 累计确认 11,011,116 字节，抓包有大量重传和乱序，最终报告“AirDrop 未交付文件”；当前镜像复验同样未交付，退出时记录 `stopped cleanup=0 rc=0` 和 `released`。

复验期间 iPad 对该对端记录了 31 次固件缓存删除，并有 AWDL AF 解析错误 reason 1 及随后恢复。板端采样的 TID 0 仍为 `BA_ON`，最终累计两次 ADDBA 请求、一次响应。原生速率表的第二组计数是成功数，不能误读为失败数；这些计数属于固件全局，不能直接等同于该对端。对端缓存重建与聚合会话恢复的关系尚未证实，不能据此宣称已定位唯一根因。

尚未通过的验收包括 iPad Pro 系统 AirDrop 双向完整文件、内容校验、实际聚合收发、单／多连接、取消重试、重连，以及传输后的队列清理和长期稳定性。蓝牙 HCI、NAN 合簇、AWDL 对端建立和接收弹窗均不能替代文件验收。活动 NDP 与 AWDL 并发的吞吐与公平性也未验收。

真实可用窗口 OPEN 成功后，针对自有 SCB 补跑原生每 TID 的 BA 恢复，最多每原生 watchdog 秒一次。调用禁止重复周期老化，保留原生 BAR／DELBA、重试期限和包引用回收；不会强制离开窗口的对端可用。原生 watchdog 时钟已实机确认递增。该修复针对分时窗口下可能错过恢复机会的缺口，尚未证明它是此前交付失败的唯一原因，也尚未通过文件交付验收。为保持原有固件内存边界，删除三处 NAN 重复调试打印；错误返回和资源所有权检查保留。

BAR 注册回调只为自有 AWDL SCB 补齐被消费事件的收尾。A2 的包回调分发器在调用后无条件释放该回调记录；发送包释放路径会传入状态 0，而原生 BAR 回调会在清除等待标志前提前返回。补丁保留原始状态传给原生处理，仅对这类已被消费的回调清除等待标志、安排正常可用窗口重试，不合成 ACK、不直接发送、不修改其他站点。直接调用原生 BAR 函数的路径不变。固定注册指针原始字节与逆向还原已通过构建检查；真实文件交付仍需验收。

## 接收端发送者选择

原生接收站点查找对发往本机 AWDL NDI、来自未选中发送者的有效单播数据，上报携带会话代次与六字节源 MAC 的 `BCM_AWDL_SENDER` 事件。DHD 与宿主校验事件后转换为公共 `sender-requested`；公共 AirDrop 接收器在没有活动请求或上传时释放旧连接，再选择实际发送者。固件不在接收路径替换 SCB，不将组播发现、管理帧或空数据帧当作选择请求。

AWDL 地址取 NMI 地址、置本地管理位并将最后一字节异或 2；普通 NAN 默认 NDI 使用异或 1。这样对端选择引起的释放和重新申请保留接收端 IPv6 地址，使已开始的 TCP 重试仍能到达。显式配置的地址冲突仍由原生 NDI 创建检查拒绝；会话代次继续使用随机值。

iPad Pro 的反向验收已进入系统 AirDrop 选择界面，但未发现接收端。记录显示板端选择了另一台设备；iPad 收到其 mDNS 公告后，向 8771 端口重复发送 SYN，没有收到 SYN-ACK。旧实现没有发送者选择事件；这些证据不证明每个 SYN 已到达固件。结束后 `cleanup=0`、`released`、AirDrop idle。该次板端抓包因文件权限失败，不能作为双端抓包证据。新事件路径与稳定地址候选已部署，固件 SHA-256 为 `3dfa59987fe4c116f1c62cf8936ebd315a6ae3804cce9de7ba7f03a103c84468`；驱动、宿主与固件均完成构建并核对部署摘要，保留原有 56 KiB 固件保留区，剩余 64 字节。首次反向复验在 Files 搜索导航阶段失败，尚未触及文件传输；接收器停止后为 idle，AWDL 接口已释放。已修复既有 UI 测试的侧栏单元格定位。发送者事件的真机效果、双向传输、内容一致性及重连仍未通过。
