空口诊断记录的 PHY 修改命令中位耗时约 23 ms；传输起步仍有低速阶段。固件发送队列持续有待发数据，已采集的接收端 AP 流量很少，现有证据不支持将该轮瓶颈归因于主机供数不足或接收端大量 AP 下载。日程变化、信道切换和起步阶段影响整文件均速。NAN 与切换的隔离结果见后文。

## 已知限制

- iPad 接收失败后可能保留挂起的系统会话，出现已开启“所有人”但不再弹窗的状态；需要恢复系统接收服务或重启设备。真机 UI 测试要求设备已解锁。
- BE200 已完成 Linux → iPad 的系统 AirDrop 小文件与 500 MB 发送。单频发现策略下，mini 本轮新增配对的缓存连接及无线服务重启后重连通过；更早建立的 BE200 配对记录、活动 NDP 与 AWDL 并发传输、反向接收和长期稳定性尚未完成本轮验收。
- 保持 AP 连接的五轮达标结果覆盖上述 iPad mini、161 主信道 AP、149 / 161 AWDL 跟随及同一 500 MB 文件；不同接收设备、无线干扰环境和长时间运行尚未覆盖。
- 单频 NAN 发现策略下，记录过一次接受后持续 TCP 重传、90 秒后未交付的失败：TCP 仅确认约 1.74 MB，拥塞窗口降至 4–5 个报文，内核没有新增固件错误或队列警告。该失败的触发条件尚未确定；候选查询超时后切换并重试目标的 500 MB 验收已通过。
- `NAN_PEER_CMD` 曾触发 c108 固件断言 `0x20103330`，驱动随后自动恢复；触发条件尚未确认。缓存认证站点改动的 RTL 真机回归尚未完成。
- AWDL 跟随范围为同一 80 MHz 频块内的 149 / 161；活动 NDP 数据站点要求保留 NAN 主信道，此时 AWDL 使用该主信道上的公共时隙。并发传输与该回退路径尚未完成真机验收。
- 服务发现仍受总期限约束；多个不响应的候选设备可能耗尽期限。首轮查询失败后，同一请求重试并完成交付已通过真机验收。

- RTL 服务重启后也观察到超过 5 秒窗口的发现延迟；发现延迟的触发条件尚未定位。
- Wi-Fi Aware 的新配对、整机重启、持续吞吐和长期可靠性尚未完成整体验收。
- 一个守护进程管理一块网卡，使用固定 nan0/ndi0。BE200 backport 替换 cfg80211/mac80211，两个硬件包不能据此视为可同时运行。
- RTL 仅支持一个活动数据站点，活动站点不支持更换为不同密钥。
- U2 重建使用带 MIPS16 后端的 Clang 21 与 GNU MIPS binutils；固件下载格式要求原项目的摘要处理与数组长度核对。
- BE200 原 main 的 Rust 真机结果包含低速 NDP 与连接超时案例，尚无 30 分钟持续验收。RTL 原 main 已完成连接后调度与退出修复，长期连接可靠性和持续性能仍需对应设备证据。
