## 已知限制

- iPad 接收失败后可能保留挂起的系统会话，出现已开启“所有人”但不再弹窗的状态；需要恢复系统接收服务或重启设备。真机 UI 测试要求设备已解锁。
- BE200 已完成 Linux → iPad 的系统 AirDrop 小文件与 500 MB 发送；活动 NDP 与 AWDL 并发传输、反向接收和长期稳定性尚未完成验收。
- BE200 500 MB AirDrop 已测得超过 RTL 基线的结果，但尚未达到稳定不低于 20.71 MB/s 的水平。已观测到 BBR ProbeRTT 将拥塞窗口降为 4 段、TCP 重复发送及固件速率回退；这些因素各自对吞吐波动的贡献尚未完全分离。
- BE200 原生 AWDL 使用配置选定的单个主信道（149 或 161），不跟随对端切换其他信道；吞吐取决于对端在该信道上的可用窗口，当前结果限于上述 iPad 与文件。
- BE200 backport 在 hostap 被强制终止后，异步销毁 NAN 接口的群组密钥清理可触发 `iwl_mld_get_key_sta_mask` 内核警告；该异常清理路径尚未修复。正常停止及立即重启已通过。
- 同一 iPad 保持 RTL 客户端连接时，BE200 服务发现存在超过 5 秒验收窗口的情况。两个客户端安装身份分别连接与重连已通过，并发连接尚未完成验收。
- RTL 服务重启后也观察到超过 5 秒窗口的发现延迟；发现延迟的触发条件尚未定位。
- Wi-Fi Aware 的新配对、整机重启、持续吞吐和长期可靠性尚未完成整体验收。
- 一个守护进程管理一块网卡，使用固定 nan0/ndi0。BE200 backport 替换 cfg80211/mac80211，两个硬件包不能据此视为可同时运行。
- RTL 仅支持一个活动数据站点，活动站点不支持更换为不同密钥。
- U2 重建使用带 MIPS16 后端的 Clang 21 与 GNU MIPS binutils；固件下载格式要求原项目的摘要处理与数组长度核对。
- BE200 原 main 的 Rust 真机结果包含低速 NDP 与连接超时案例，尚无 30 分钟持续验收。RTL 原 main 已完成连接后调度与退出修复，长期连接可靠性和持续性能仍需对应设备证据。
