短 TCP ACK 队列没有大包经验速率样本，原先一直逐帧等待固件完成。`0031` 使已取得的 PHY 反馈参与发送预算，接收诊断的 RTT 中位数由约 65 ms 降至约 11 ms。系统 TCP 接收自动调优上限设为 32 MiB，观测到的公告接收窗口由约 1.58 MB 增至约 8.4 MB；内核按连接需要分配。文件小块合并写入后，一次 500 MB 上传的文件写调用由约 33,909 次降至 668 次。

接收聚合能力使用本机 NAN PHY 的 11,454 字节 MPDU 与 1 MiB A-MPDU 上限。实际数据使用双流 HE80，100 ms 接收采样曾达到 91.36 MB/s；数据站点、BAID 和硬件重排队列有效。用户态接收线程约占一个 A55 核的 32%–36%，这些样本未显示持续 CPU 饱和。

NAN 发现与 AWDL 信道切换分别影响可接收时间。原生后端报告周期性 NAN 空隙，公共公告排除重叠时隙；实测 PHY 切换通常为 23–29 ms，连续接收会话观测上界为 38.08 ms，提前预留切换窗口。控制帧采用驱动入口时间校准日程，观测到的驱动到用户态接收线程延迟最高约 17.97 ms。标准日程为 16 个 64 TU 条目，局部空隙会使整个条目关闭；对端日程与 NAN 相位变化仍会改变有效接收时间。

均速按接受至接收完成事件计算，峰值使用 100 ms 文件大小采样的 5 秒滑动窗口；二者均以原文件字节数计，单位十进制 MB/s。每轮接收文件与板端保留原文件逐字节比较，并执行 `sync -f`。刷盘耗时单独记录，不包含在协议接收均速内。

## 已知限制

- iPad 接收失败后可能保留挂起的系统会话，出现已开启“所有人”但不再弹窗的状态；需要恢复系统接收服务或重启设备。真机 UI 测试要求设备已解锁。
- BE200 已完成 Linux → iPad 的系统 AirDrop 小文件与 500 MB 发送。单频发现策略下，mini 本轮新增配对的缓存连接及无线服务重启后重连通过；更早建立的 BE200 配对记录、活动 NDP 与 AWDL 并发传输和长期稳定性尚未完成本轮验收。
- BE200 与 RTL8852BE 均已覆盖单个 iPad mini 的反向 AirDrop；多个发送者同时上传尚未完成真机验收。RTL 的 AWDL 与 NAN 仍互斥。
- RTL 原部署在约 22 小时 NAN 运行后停止时，原生清理返回 `-5`，持久 NDI 未释放，并出现固件 L2 错误；正常重启后恢复。该退出问题的触发条件尚未定位。
- RTL 的 22 补丁基线连续接收第 7 轮在系统“已发送”事件及完成页面文本保存后，Xcode Runner 于截图阶段异常退出；十轮实际交付、AP 连接、内容比对和刷盘均有证据，完整 UI 测试进程为 9/10 通过。
- RTL 的 30 补丁候选连续接收第 7 轮测试进程提前退出，未取得 iPad 完成状态及完整结果包；板端已完整接收、发送成功响应、比对内容并刷盘。这一轮计入吞吐样本，但不计为完整双端 UI 验收通过。
- RTL 反向接收稳定 50 MB/s 尚未达标。候选十轮总均速为 7.200 MB/s，仍有超过 100 ms 的数据停顿、接收重排期限触发及对端以 reason 39 关闭聚合确认会话；残余吞吐波动的根因尚未确定。
- RTL 的 30 补丁候选已完成 AWDL 接收及资源释放验收；共享原生接收锁改动下的既有配对 NDP 回归尚未完成。
- BE200 反向接收稳定 50 MB/s 尚未达标；标准 64 TU 日程对部分空隙的整槽预留、对端日程变化及板载 eMMC 刷盘余量仍限制持续吞吐。
- 上游 DVZip 接收解码器在真实 iPad 上传中出现过 `bad chunk length`；该格式尚未通过连续接收验收，当前接收公告使用 gzip 能力。
- BE200 整套模块热重载出现过 order-7 连续内存分配失败及 NIC 初始化失败；该热重载问题尚未修复。
- 保持 AP 连接的扩展样本中，12 轮常规发送均速为 33.076–57.781 MB/s，总字节／总时间为 48.973 MB/s；稳定 50 MB/s 尚未达标。覆盖范围为上述 iPad mini、161 主信道 AP、149 / 161 AWDL 跟随及同一 500 MB 文件。
- 单频 NAN 发现策略下，记录过一次接受后持续 TCP 重传、90 秒后未交付的失败：TCP 仅确认约 1.74 MB，拥塞窗口降至 4–5 个报文，内核没有新增固件错误或队列警告。该失败的触发条件尚未确定；候选查询超时后切换并重试目标的 500 MB 验收已通过。
- `NAN_PEER_CMD` 曾触发 c108 固件断言 `0x20103330`，驱动随后自动恢复；触发条件尚未确认。缓存认证站点改动的 RTL 真机回归尚未完成。
- AWDL 跟随范围为同一 80 MHz 频块内的 149 / 161；活动 NDP 数据站点要求保留 NAN 主信道，此时 AWDL 使用该主信道上的公共时隙。并发传输与该回退路径尚未完成真机验收。
- 服务发现仍受总期限约束；多个不响应的候选设备可能耗尽期限。首轮查询失败后，同一请求重试并完成交付已通过真机验收。
- 同一 iPad 保持 RTL 客户端连接时，BE200 服务发现存在超过 5 秒验收窗口的情况。两个客户端安装身份分别连接与重连已通过，并发连接尚未完成验收。
- RTL 服务重启后也观察到超过 5 秒窗口的发现延迟；发现延迟的触发条件尚未定位。
- Wi-Fi Aware 的新配对、整机重启、持续吞吐和长期可靠性尚未完成整体验收。
- 一个守护进程管理一块网卡，使用固定 nan0/ndi0。BE200 backport 替换 cfg80211/mac80211，两个硬件包不能据此视为可同时运行。
- RTL 仅支持一个活动数据站点，活动站点不支持更换为不同密钥。
- U2 重建使用带 MIPS16 后端的 Clang 21 与 GNU MIPS binutils；固件下载格式要求原项目的摘要处理与数组长度核对。
- BE200 原 main 的 Rust 真机结果包含低速 NDP 与连接超时案例，尚无 30 分钟持续验收。RTL 原 main 已完成连接后调度与退出修复，长期连接可靠性和持续性能仍需对应设备证据。
